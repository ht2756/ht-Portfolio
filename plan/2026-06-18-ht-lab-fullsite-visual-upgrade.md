# HT Lab Full-Site Visual Upgrade Plan

> 状态：待实施
> 创建时间：2026-06-18
> 目标：将 HT Lab 从首页初版升级为完整、酷炫、可展示的个人独立站

---

## 一、目标摘要

将 HT Lab 从“首页初版 + 四个占位子页”升级为完整个人站。

保留当前简洁 terminal 启动样式，不做夸张 IDE 化；整体视觉采用克制电影科技风：暗色基底、精细网格、玻璃层、低饱和发光、顺滑滚动动效。

本轮允许使用虚构但高质量的展示内容，目标是先完成一个视觉饱满、结构完整、可演示的个人独立站，后续再替换真实项目、PPT、链接和 AI 接口。

最终完成后必须全局感受一遍：这个站是否真的像一个很不错的个人站，是否有鲜明个人风格，是否能完整展示开发、设计、AI、成长四条线，而不是像原型拼接或组件堆叠。

---

## 二、核心原则

- 保留当前 terminal 的简洁风格，只做细节优化，不恢复夸张 IDE 文件树版本。
- Terminal 以当前 `TerminalBoot.tsx` 为准：仅保留 macOS 标题栏 + 命令输出，不加入 Explorer、文件标签、行号、状态栏。
- 可以大量更新和扩展，不局限于小修小补。
- 优先完成个人站的整体质感、展示完整度和访问路径。
- 内容可以大胆虚构，但要保持专业可信，后续方便替换真实资料。
- 全站要统一，但四个板块仍要有各自清晰性格。
- 动效服务于叙事和高级感，不堆砌炫技。

---

## 三、视觉方向

### 3.1 全站基调

- 方向：克制电影科技风
- 关键词：terminal、实验室、作品档案、滚动叙事、玻璃层、细网格、低饱和光效
- 避免：强赛博、过度霓虹、太多 emoji、营销页式大空洞、普通后台模板感

### 3.2 首页

首页是 HT Lab 的品牌入口，需要从“能看”升级为“有记忆点”。

需要强化：

- terminal 启动后的品牌出现仪式感
- Hero 的视觉冲击和文字层级
- 四个板块预告卡片的差异化
- 双人介绍的可信度和个人感
- 技术栈、CTA、Footer 的完成度

### 3.3 子板块

四个子板块需要风格独立，但仍属于 HT Lab：

| 板块 | 方向 | 目标 |
| --- | --- | --- |
| Dev Zone | 暗色开发者仪表盘 | 展示全栈能力、项目经验、技术栈 |
| Design Zone | 明亮高级作品画廊 | 展示 PPT / UI / 品牌视觉能力 |
| AI Lab | 深色未来感聊天实验室 | 展示 Dify / AI 学习与实验能力 |
| Growth Log | 温暖知识时间线 | 展示持续学习、笔记、技能成长 |

## 四、实施范围

### 4.0 当前实现基线

- 已新增并应继续复用：`src/data/siteContent.ts`、`src/components/SiteShell.tsx`、`src/components/SectionHeading.tsx`、`src/components/StatStrip.tsx`。
- 不要重复创建平行的数据文件或平行壳层组件。
- 当前四个 Coming Soon 子页仍需要接入这些共享组件并完整实现。
- `ui/prototype/*.html` 作为信息架构和视觉参考，不逐像素迁移。
- 必须迁移的结构为：首页 terminal/四区入口，Dev 指标 + 项目 + 贡献轨迹，Design 分类 + 作品网格，AI 静态聊天面板 + 能力卡，Growth 月份时间线 + 笔记/外链/详情卡。

### 4.1 全站视觉系统

- 重整 `globals.css` 中的 CSS variables。
- 统一 section 间距、最大宽度、移动端 padding。
- 统一卡片、按钮、标签、边框、阴影、毛玻璃、背景网格。
- 减少当前页面中“局部好看但整体散”的问题。
- 控制颜色数量，避免首页变成紫蓝渐变泛滥。

### 4.2 首页升级

- 保留 `TerminalBoot` 现有简洁终端方向。
- 优化 terminal 移动端宽度、行距、阴影、淡出节奏。
- 强化 Hero 的电影感与品牌感。
- 将四个板块入口从普通卡片升级为“风格预告区”。
- About 区突出夫妻档身份和分工。
- Tech Stack 区更像能力陈列，而不是普通标签堆。
- CTA 区提供明确路径：看开发作品、看设计作品、联系合作。

### 4.3 子页面完整化

当前四个子页都是 Coming Soon，需要全部做成可展示页面。

所有子页必须使用 `<SiteShell variant="dev|design|ai|growth">` 包裹；不得在页面内重复手写 Navigation/Footer。首页可保持现有 TerminalBoot + Navigation/Footer 结构。

#### Dev Zone

内容包括：

- 页面 Hero：开发者工作台 / 系统状态感
- 项目卡片：B 端系统、小程序、AI 工具、内部效率平台
- 技术栈：前端、后端、部署、工具
- 贡献热力图或活动轨迹
- 项目指标：交付数、模块数、技术栈覆盖、可复用组件
- 最低数量：至少 3 个项目、4 个统计、4 类技术栈、1 个贡献/活动轨迹。

#### Design Zone

内容包括：

- 页面 Hero：Professional Presentation Portfolio
- PPT / 视觉作品卡片
- 分类标签：品牌设计、商业提案、教育培训、活动策划
- 作品统计：作品数、分类数、客户类型、浏览量
- 封面视觉要足够精致，避免普通白卡片堆叠
- 最低数量：至少 6 个作品、4 个分类、4 个统计。

#### AI Lab

内容包括：

- 模拟 Dify 聊天助手界面
- AI 能力卡片：知识库、工作流、Prompt、Agent
- 学习记录：Dify、RAG、工作流编排、API 对接
- 模型状态 / 实验状态视觉
- 暂不接真实 API，先做静态可演示体验
- 最低数量：至少 1 个静态聊天面板、4 个能力卡、4 条学习记录。

#### Growth Log

内容包括：

- 成长时间线
- 笔记卡片
- 外链卡片
- 详细记录卡片
- 技能标签和月份分组
- 氛围要温暖，但不能幼稚
- 最低数量：至少 6 条记录、2 个月份分组、3 种卡片类型。

### 4.4 数据和组件结构

- 新增共享数据文件，例如 `src/data/siteContent.ts`。
- 将虚构项目、PPT、AI 能力、成长日志、统计数字集中管理。
- 抽出通用组件：
  - 页面 Hero
  - Section heading
  - Stat card
  - Tag / Badge
  - CTA band
  - Project / Work / Log card
- 页面负责组合展示，避免每个页面都写成巨大硬编码文件。

### 4.5 国际化

- 补齐中文和英文文案。
- `/zh` 和 `/en` 体验保持一致。
- 子页面不再只写英文标题和英文 Coming Soon。
- 导航、首页固定文案继续放 `zh/en.json`。
- 作品、项目、AI、Growth 展示数据放 `siteContent.ts` 的 `LocalizedText`。
- 页面不得硬编码只含英文或只含中文的核心展示文案。

### 4.6 导航和页脚

- 子页统一接入 Navigation 和 Footer。
- 导航当前所在页状态要准确。
- Footer 链接需要带当前 locale。
- 移动端菜单不能遮挡或无法关闭。

### 4.7 文件级任务

1. `globals.css`：统一视觉变量和通用类。
2. `siteContent.ts`：补全四区数据和中英文字段。
3. `SiteShell` / `SectionHeading` / `StatStrip`：接入全站壳层和基础展示组件。
4. `dev-zone/page.tsx`：实现 Dev Zone。
5. `design-zone/page.tsx`：实现 Design Zone。
6. `ai-lab/page.tsx`：实现 AI Lab。
7. `growth-log/page.tsx`：实现 Growth Log。
8. `SectionsPreview` / `AboutSection` / `CTASection`：对齐新视觉和行动路径。
9. `Navigation` / `Footer` / `validate-fullsite.mjs`：完成 locale、可访问性和验证收尾。

## 五、验收标准

### 5.1 基础验收

- `npm run lint` 无 ESLint warning/error。
- `npm run build` 构建通过。
- `npm run validate:fullsite` 必须通过；脚本检查 Coming Soon、SiteShell 接入、核心数据数组长度、中英文 locale 覆盖。
- 以下路由可访问：
  - `/zh`
  - `/en`
  - `/zh/dev-zone`
  - `/zh/design-zone`
  - `/zh/ai-lab`
  - `/zh/growth-log`
  - `/en/dev-zone`
  - `/en/design-zone`
  - `/en/ai-lab`
  - `/en/growth-log`

### 5.2 视觉验收

桌面端和移动端都要检查：

- terminal 不裁切、不遮挡。
- 导航不遮挡页面主体。
- 所有按钮文字不溢出。
- 卡片标题、描述、标签不重叠。
- 页面没有大片空白和断层。
- 四个子页不再出现 Coming Soon。
- 首页和子页看起来属于同一个品牌。
- 每个板块都有独立视觉性格。
- 启动 `npm run dev` 后，用 1440x900、390x844 两个视口检查 `/zh`、`/en` 和 8 个子路由，记录遮挡、溢出、大片空白、导航无法关闭、terminal 裁切等问题。

### 5.3 个人站体感验收

最终完成后必须全局浏览一遍，并从陌生访客视角判断：

- 第一眼是否能知道这是 HT Lab 的个人站。
- 是否能看出 HT 是全栈开发者，太太是 UI / PPT 设计师。
- 是否能看出这是一个夫妻档创意实验室。
- 是否有足够酷炫但不过度的视觉记忆点。
- 是否有完整展示，而不是只有概念和占位。
- 是否有真实个人站的节奏：入口、介绍、作品、能力、成长、联系。
- 是否愿意继续点进子页面看内容。
- 是否适合作为未来求职、接单、自我展示的基础。

如果以上体感不达标，需要继续调整，不以“代码跑通”作为完成标准。

## 六、交叉审查流程

开发完成后执行三轮审查：

### 第一轮：代码审查

检查：

- 组件是否过大。
- 数据是否散落在页面里。
- 样式是否重复严重。
- i18n 是否缺 key。
- 链接是否缺 locale。
- 是否有无用 import、无效类名、硬编码风险。

### 第二轮：视觉审查

检查：

- 首页整体是否有品牌感。
- 四个子页是否完整。
- 颜色是否高级且统一。
- 卡片间距是否舒服。
- 动效是否顺滑。
- 移动端是否像认真适配过。

### 第三轮：个人站体感审查

完整从首页开始浏览：

1. 看 terminal 和 Hero 的第一印象。
2. 看四个板块预告是否让人想点击。
3. 分别进入四个子页面。
4. 回到首页看整体记忆点。
5. 判断是否已经像一个优秀个人站，而不是一个演示页面。

审查结论必须明确：

- 通过：可以交付。
- 不通过：列出最影响个人站质感的 3-5 个问题并继续改。

## 七、技术约束

- 使用现有技术栈：
  - Next.js App Router
  - TypeScript
  - Tailwind CSS v4
  - Framer Motion
  - GSAP
  - next-intl
  - lucide-react（已在 `package.json` 中存在，可用于按钮和状态图标；不要新增其他 UI/icon 库）
- 不引入后端。
- 不接真实 Dify API。
- 不实现真实 PPT 在线翻页系统。
- 不新增复杂 CMS。
- 不依赖 git diff，因为当前目录不是 git 仓库。

## 八、默认假设

- 本轮可以大量更新和扩展。
- 内容可以虚构，但要专业、有展示价值、后续可替换。
- terminal 当前样式保留。
- 最终目标不是“页面能跑”，而是“像一个完整、酷炫、有个人风格的个人站”。
